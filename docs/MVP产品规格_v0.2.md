# 安记 MVP 产品设计规格 v0.2（基于用户访谈校正）

> 相对 v0.1 的校正版。仍不含实现代码。本版将 MVP 进一步收缩到单一验证目标，并把"为什么"标签、目标建立、AI 基础记账、多项高级功能移出第一版 Prototype。

## 与 v0.1 的关键差异（变更摘要）
- 核心验证目标收窄为一条：用户是否愿意以极低成本记录消费，并逐步理解自己的消费行为。
- Why Tag 由"记录时必填"改为"后置补充 / 回顾"，Quick Log 控制在 3–5 秒。
- 目标建立改为 Optional，Onboarding 不强制。
- 首页核心指标由"本月为未来存下 X"改为"我的钱怎么被使用"，目标进度降为可选模块。
- 移出 MVP：多账户聚合、复杂洞察、OCR、对话式查询、AI 目标建议（进入 Future Roadmap）。
- AI 不负责基础记账，MVP 用 Rule-based 分类；保留 AI Insight V1 设计供后续展示。
- North Star 重定义为用户价值本身，WULLR 作为 Proxy Metric 追踪它（见下）。

## 保留的核心原则
非评判 · 低摩擦 · 目标导向（连接未来，而非节俭施压）· 用户自主权。

---

## North Star & Proxy Metric (v0.2)

**North Star（我们要验证的用户价值）**
= 用户愿意以极低成本持续记录消费，并逐步理解自己的消费行为（即 v0.2 的单一核心验证目标本身）。

**Proxy Metric：周度"理解闭环率"（Weekly Understanding Loop Rate, WULLR）**
由于"理解"与"习惯"难以直接度量，我们用一个可观测的行为代理指标来追踪 North Star：
= 当周既完成 ≥1 笔记录、又主动打开 Insight 或补充 ≥1 个 Why 标签的 UV ÷ 当周活跃记录 UV。
目标：第 4 周 ≥ 40%。

**为什么 WULLR 是一个合适的 Proxy（而非心安度）：**
1. **行为是价值证据，态度会被污染**：心安度是主观感受，受当日心情、外部环境大量影响，且变动慢、难以归因到产品改动；WULLR 是可直接观测的用户行为。
2. **同时覆盖验证目标的两条线**：记录（输入）+ 理解（输出）。只记录不看 = 没"理解"，闭环未关闭，产品第二承诺落空。
3. **领先且难作弊**：若团队只堆记录功能，Proxy 不会动——必须让用户真的去理解，才涨。这逼团队守住"理解"价值。
4. **周频可行动**：每周可读，便于迭代，不像心安度要长期问卷。

**护栏指标（不是 North Star，但须监控）：**
- WAR-d（周活跃记录天数，习惯底线，目标 ≥3 天/周）
- 记录完成率与单笔耗时中位数（目标 ≤5s）
- 负面情感反馈率（"被评判 / 焦虑"关键词，红色护栏）
- 提醒关闭率（过高说明打扰）

## A. MVP v0.2 Feature Map

| 优先级 | 功能 | 说明 | 验证目的 |
|---|---|---|---|
| Must | Quick Log（极简记录） | 金额 → 规则自动分类 → 一键完成，3–5 秒；Why Tag 不在此步 | 验证极低摩擦记录意愿 |
| Must | 账单导入 | 支付宝/微信/信用卡 CSV/PDF 解析为交易（非"聚合视图"） | 极低成本的批量记录 |
| Must | Rule-based 自动分类 | 关键词/商户规则分类 | 让数据可读，零模型成本 |
| Must | Home：我的钱怎么被使用 | 支出总览 + 分类分布 + 趋势；目标进度为可选模块 | 验证"初步理解"无需复杂洞察 |
| Must | Insight（基础理解） | 分类趋势 + 后置 Why 分布 + 规则生成一句理解 | 验证理解闭环 |
| Must | 后置 Why Tag | 在 Insight/回顾中自愿补充，非记录必填 | 降低记录摩擦 |
| Should | 目标建立（Optional） | 用户主动建，Onboarding 不强制 | 验证目标是"锦上添花"非门槛 |
| Should | 目标进度模块（可选展示） | Home/目标页，用户开启后显示 | 同上 |
| Won't | 多账户聚合 / 复杂洞察 / OCR / 对话查询 / AI 目标建议 / 强制预算报警 / 社交排名 / 理财推销 | 移出第一版 Prototype | 见 Future Roadmap |

> MVP 不做 AI 基础记账（用 Rule-based）。AI 仅保留在 Future V1 设计。

## B. 修改后的 User Flow

**A. 接入（Onboarding，无强制目标）**
1. 欢迎：说明"我们不打分、不批评，先帮你看看钱怎么花"
2. 轻量导入 或 直接记一笔（让用户立刻体验低摩擦）
3. （可选）建立 1 个目标，或"先跳过，看看钱怎么被使用"
4. 进入 Home

**B. 每日记录（核心，3–5 秒）**
1. 打开 / 快捷入口
2. 输入金额 → 系统给出分类建议
3. 一键完成（无 Why、无目标打断）
4. 中性提示："记好了"

**C. 理解（后置，非每日强制）**
1. 任意时刻打开 Insight：看"钱怎么被使用"
2. 自愿给部分交易补 Why Tag（"想了解为什么？标记几笔"）
3. 规则生成一句理解（非评判）

**D. 目标（全程 Optional）**
1. 用户从 Home 可选模块或目标页主动建立
2. 进度仅在用户开启后展示

（闭环：记录 → 理解 → 持续记录；目标为旁路可选）

## C. 三个核心页面

### 1. Home — 我的钱怎么被使用
- **目的**：让用户一眼看清"钱花在哪、怎么变的"，而非"为未来存了多少"。
- **布局**：
  - 顶部：本月支出总览（金额 + 环比）
  - 主区：分类分布（环形/条形）+ 近 6 月趋势
  - 可选模块：目标进度（用户开启后才出现）
  - 次区：最近记录列表
- **关键交互**：文案中性；不出现"超支 / 为未来存下"等施压或储蓄导向表述。

### 2. Quick Log — 3–5 秒完成
- **目的**：把记录成本压到最低，形成习惯。
- **布局**：
  - 大数字键盘（默认弹出）
  - 金额输入区
  - 规则自动分类 chip（建议置顶，可改）
  - 完成按钮「记好了」
  - （Why Tag / 目标 不在此页；提供"稍后补充"入口，后置到 Insight）
- **关键交互**：金额输入后自动带出上次/同类分类；步骤 ≤3 步，单笔耗时目标 ≤5s。

### 3. Insight — 理解消费模式
- **目的**：把"花了"变成"怎么花、为什么、连到哪（若用户有目标）"。
- **布局**：
  - tab1 趋势：分类 + 月度环比（基础，非复杂洞察）
  - tab2 为什么：用户补充的 Why 分布；未补则温和引导
  - tab3 轻回顾：规则模板生成的一句理解
  - 目标连接（可选）
- **关键交互**：所有提问非评判；评分/标记不排名、不对外。

## D. MVP 核心假设

- **H1**：用户愿意以极低成本（≤5 秒/笔或一键导入）持续记录消费。
- **H2**：去掉强制 Why Tag 与强制目标后，记录摩擦下降，记录意愿反而上升。
- **H3**：用户仅通过基础趋势/分类（"钱怎么被使用"）即可初步理解消费，无需复杂洞察或 AI；理解程度由 Comprehension Test 客观检验（而非仅看浏览）。
- **H4**：非评判、低干预的语气不易引发焦虑，比"预算/羞耻"类工具更易坚持。
- **H5**：Rule-based 分类可在 MVP 阶段满足用户需求（准确率需实测，不预先假设具体数值）。
- **H6**：目标/储蓄是"锦上添花"而非"入门门槛"——用户可先探索消费，再决定是否设目标。

> 数据模型影响（非新功能）：WhyTag 与 Goal 在 v0.2 中均为可选；Transaction.why_tag / goal_id 允许为空，分类由 rule 引擎填充。

## E. 假设验证方法

| 假设 | 验证方法 | 成功信号 / 失败信号 |
|---|---|---|
| H1 | 埋点漏斗：记录开始→完成耗时分布、WAR-d、D7/D30 留存；可用性测试观察是否顺手 | 成功：单笔耗时中位数 ≤5s，WAR-d≥3，D30 留存健康；失败：>10s 比例高或留存骤降 |
| H2 | 前后/对照：v0.1(强制) vs v0.2(可选) 的记录完成率与放弃率；Quick Log 步骤数减少后的转化变化 | 成功：完成率上升、放弃率下降；失败：无差异或下降 |
| H3 | Insight 周访问率、停留时长、自愿 Why 补标率；Comprehension Test：浏览 Insight 后弹出轻量认知题（如"你这月花得最多的是哪一类？"多选），答对即理解信号；辅以自报告"看完更理解了吗？" | 成功：Insight 访问率/补标率随周上升，且 Comprehension Test 正确率随周提高；失败：无人打开 Insight 或测试正确率无提升 |
| H4 | 负面情感反馈率（"被评判/焦虑"关键词）、提醒关闭率 | 成功：负面率低于阈值、关闭率低；失败：出现批判感反馈 |
| H5 | 规则分类准确率（人工抽样标注对照）、用户手动改分类比例 | 成功：实测准确率达到可用性门槛、改分类率处于低位（阈值由观测数据定，不预设 80%）；失败：改分类率过高 → 提前引入 ML |
| H6 | Onboarding 跳过目标比例、后续(D14)主动建目标比例 | 成功：多数跳过但部分后续自建（目标确为加分项）；失败：几乎无人建（重新评估目标定位，但仍不强制） |

## F. Future AI Roadmap

> 严格限于用户访谈指定的范围，不新增未验证功能。AI 不负责 MVP 基础记账（Rule-based 已覆盖）。

**V1（AI Insight，保留供后续 AI PM 作品展示）**
- AI 非评判式月度回顾 / 消费理解文案生成（替代规则模板，更自然、更共情）
- AI 温和趋势提示（"这月外卖多，是不是忙？"——提问非警告）

**V2**
- 截图 / OCR 自动记账（零输入，进一步降摩擦）
- 对话式查询（"我上月奶茶花多少？"）
- 多账户聚合视图（统一余额与流水）

**V3**
- AI 目标连接建议（"你常喝奶茶，要不要设个'小确幸基金'？"）
- 个性化消费模式洞察 / 预测

**原则坚守**：即便进入 AI 阶段，也不做理财推销、代付、社交排名、强制预算报警——守住非评判与用户自主权。
