# 安记(Ānjì) 增量 PRD：记账数据「查找 / 修改 / 删除」管理

> 范围说明：本增量 PRD 仅描述本次变更部分，不重复旧 PRD 的全局内容（产品背景、完整数据模型、Home/Insight 等既有能力）。

## 1. 增量概述

在 Quick Log「记一笔」页下半部新增「我的记录」管理区，补齐"记完一笔后无法查看、纠错、清理"的核心缺口，让用户在**极低摩擦、非评判**的前提下管理自己的交易数据。

## 2. 变更范围与边界

### 2.1 新增 / 复用 / 不动

- **新增**：Quick Log 页「我的记录」管理区（搜索/筛选条 + 交易列表 + 每行【编辑】/【删除】入口；撤销为 P1）。
- **复用**：
  - 本地存储：沿用 IndexedDB（降级 localStorage），按现有「读全部 → 改内存 → `putTxns` 整批回写」模式落地单条变更。
  - 同步机制：复用 `cloud.js` 的 `pushTxns` + `server/api.js` 的 `POST /api/txns/sync`；删除 = 打 `_deleted:true` 后增量推送，修改 = 更新字段 + `updatedAt` 后推送（last-write-wins）。
  - 分类体系：复用现有 `catKey` 规则分类 chip。
- **不动**：
  - Home 页「最近记录」预览（#home-recent）保持原样，仅作预览，不接管理入口。
  - 底部导航三项（消费 / 记一笔 / 理解）不变。
  - 服务端同步逻辑（`server/api.js`）不动，不引入新同步协议。
  - Insight（理解）页不动。

### 2.2 涉及文件清单

| 文件 | 变更 | 说明 |
|------|------|------|
| localdb.js | **改** | 新增便捷 API：`updateTxn(id, patch)`（单条更新字段+`updatedAt`）、`deleteTxn(id)`（打 `_deleted` 标记）、`queryTxns({keyword, catKey, from, to})`（内存实时过滤）。内部仍走"读全部→改内存→`putTxns`整批回写"，不改现有 API 签名。 |
| cloud.js | **改** | 编辑/删除保存成功后（仅登录态）调用现有 `pushTxns` 推送变更；不改动 `_deleted`/`updatedAt` 处理逻辑。 |

| styles.css | **改** | 新增「我的记录」区、搜索条、列表行、编辑/删除按钮、温和确认弹层、中性 toast 样式；保持低摩擦视觉风格。 |

## 3. 用户故事（增量 Epic）

- **查找**：As a 记账户的我，I want 在「我的记录」里按备注/金额关键词、分类、时间范围实时筛选，so that 我能快速定位某笔交易而不必滚动一长串。
- **修改**：As a 记账户的我，I want 点某笔交易的「编辑」直接改金额/备注/分类并保存，so that 记错时能立刻温和地纠错，无需删了重记。
- **删除**：As a 记账户的我，I want 点「删除」经一次温和确认后移除这笔交易，so that 我能清理误记或不再需要的数据，保持账本干净。
- **撤销（建议 P1）**：As a 记账户的我，I want 删除后短时间内能撤销，so that 手滑误删时能即时救回，不造成数据焦虑。

## 4. 功能需求池（增量）

### 查找（P0）
- **FR-1**：「我的记录」顶部提供搜索/筛选条，支持：
  - 关键词输入：匹配 `note`（备注）与 `amount`（数值/字符串包含）。
  - 分类筛选：选择 `catKey`（含 `other` 及全部现有分类），可"全部"。
  - 时间范围：起止日期筛选 `createdAt`，可留空表示不限。
- **FR-2**：筛选实时生效（输入即过滤，无需点"搜索"按钮），列表即时刷新。
- **FR-3**：无匹配结果时展示友好中性提示（如"没有找到相关记录"），不出现错误/告警样式。
- **验收标准**：切换关键词/分类/时间范围后，列表在 200ms 内仅展示命中项；清空筛选恢复全量；空结果有提示且无报错态。

### 修改（P0）
- **FR-4**：每行提供「编辑」入口；点击进入编辑态（行内展开或弹窗，见待确认 #3）。
- **FR-5**：可编辑字段：`amount`、`note`、`catKey`；分类复用现有规则分类 chip，默认带出原值。
- **FR-6**：保存时本地更新该条字段 + `updatedAt=now()`；若登录态调用 `pushTxns` 增量推送（沿用 last-write-wins）。
- **FR-7**：编辑态文案/按钮保持中性非评判（"保存"/"取消"），不出现"你记错了"类表述。
- **验收标准**：保存后列表立即反映新值；IndexedDB 写入成功；登录态下服务端该条 `updatedAt` 被更新且下次 `pull()` 返回新值；非登录态仅本地生效。

### 删除（P0）
- **FR-8**：每行提供「删除」入口；点击弹出温和二次确认（中性语言，如"确定要移除这笔记录吗？"，非红色告警、无施压/焦虑文案）。
- **FR-9**：确认后本地逻辑删除：标记 `_deleted:true` + 刷新 `updatedAt`；经 `putTxns` 整批回写；从「我的记录」列表移除该条。
- **FR-10**：登录态下确认删除后调用 `pushTxns` 增量推送带 `_deleted` 的变更；服务端执行逻辑删除，不引入新协议。
- **验收标准**：确认删除后该条立即从列表消失；本地记录带 `_deleted:true`；登录态下 `pull()` 后服务端亦不再返回该条；Home「最近记录」是否联动见待确认 #5。

### 撤销（P1，建议）
- **FR-11**：删除确认后，在中性 toast「已删除」旁提供「撤销」入口；窗口期（建议 5s）内点击可恢复：清除 `_deleted`、恢复 `updatedAt`、重新写入并（登录态）推送。
- **验收标准**：删除后 5s 内点撤销，该条重现在原列表位置且 `_deleted` 清除；超窗口则 toast 消失、撤销不可用。

### 列表展示（P0）
- **FR-12**：每行展示：金额、分类（chip）、备注（截断）、时间（`createdAt` 友好格式）；与「记一笔」同源低摩擦风格。
- **FR-13**：交易数量多时支持滚动加载或分页（策略见待确认 #2），保证页内流畅。
- **FR-14**：列表数据源为本地全部交易（含未同步），按时间倒序，受查找筛选约束。
- **验收标准**：百条级交易下滚动/加载无明显卡顿；每行信息一目了然；筛选与列表联动正确。

## 5. 交互与文案约束（红线）

- 全程遵守「非评判·低摩擦·用户自主权」红线：不出现评判 / 施压 / 社交排名 / 理财推销。
- **删除确认**：温和中性，禁止红色告警、禁止"后悔""浪费""管不住"等焦虑词；建议文案："确定要移除这笔记录吗？"（若支持撤销可补"可稍后撤销"）。
- **成功反馈**：中性 toast，如「已更新」「已删除」「已恢复」；不加评价。
- **编辑非破坏性**：取消即还原，不留半成品。
- **查找无障碍**：空结果不渲染为空页面/报错，给中性引导。

## 6. 待确认问题（增量）

1. **删除撤销**：是否提供撤销（P1）？若提供，窗口期多长（建议 5s）？
2. **列表分页/加载**：交易多时是滚动加载还是分页？阈值多少（建议 >50 条分页/分批）？
3. **编辑形态**：编辑用行内展开还是弹窗？移动端优先哪种更稳？
4. **查找增强**：是否需要金额区间（最小~最大）筛选，还是仅关键词 + 分类 + 时间？
5. **Home 联动**：删除/修改后，Home「最近记录」预览是否需同步隐藏/更新被删条目（当前预览数据源待对齐）？
6. **本地性能**：是否需为 `queryTxns` 建索引，还是内存过滤即可（数据量级预期）？
