# 安记 (Working Title) — MVP 产品设计规格 v0.1

> 基于 Problem Statement v0.1。本文档为产品设计稿，**不含实现代码**。

## 0. 产品定位一句话

帮助用户以极低的记录成本，理解自己的消费行为，并将当下的每一笔花销与未来的目标**温柔地连接**起来——不评判，只照亮。

- **Working Name：安记 (Ān Jì)** —— 安心地记，记出安心。
- 备选名：明账 / 知微 / 悦账（待品牌确认）。

### 贯穿全文的 4 条设计原则
1. **非评判式语气**：任何文案不得出现"你又超支了""你太浪费"等指责性表达。
2. **低记录成本**：记一笔 ≤ 10 秒，且尽量自动完成。
3. **目标导向而非节俭导向**：强调"为未来存下"，而非"少花"。
4. **理解优先**：先解释"为什么花"，再谈"怎么办"。

## 1. MVP Feature Map

优先级框架：**MoSCoW**（Must / Should / Could / Won't）。

### ✅ Must Have（MVP 必须有）
| 功能 | 说明 | 为什么是 Must |
|---|---|---|
| 极简记一笔 | 金额 → 自动建议分类 → 选/确认"为什么"标签 → 完成，≤10s | 核心记录入口，低摩擦 |
| 账单导入 | 支持支付宝/微信/信用卡账单 CSV/PDF 导入并解析 | 解决"分散管理"，零手动 |
| 自动分类 | 基于商户/关键词的**规则分类**（MVP 用规则，非 AI，见 §7） | 让数据可读 |
| 消费趋势 | 月度收支、分类占比、环比 | 把"花多少"升级为"怎么花" |
| 目标建立 | 建 1–N 个目标（旅行/应急/学习），设金额与期限 | 连接未来的核心载体 |
| 心安首页 | 仪表盘展示"本月为未来存下 X / 目标进度 Y%" | 情感价值主阵地 |

### 🟡 Should Have（宜有，视资源）
| 功能 | 说明 |
|---|---|
| "为什么"轻回顾 | 每周 1 次温和提问："上周外卖里有几顿是不想做饭？" |
| 消费-目标联动 | 记一笔时可关联某目标（如"这杯奶茶从旅行基金出？"） |
| 多账户聚合视图 | 统一展示各账户余额与流水 |

### 🟢 Could Have（增强，可后置）
| 功能 | 说明 |
|---|---|
| 截图 OCR 记账 | 拍照支付截图自动生成一笔 |
| 对话式查询 | "我上月奶茶花多少？" |
| 非评判式月度回顾 | AI 生成温柔月度总结 |

### ⛔ Won't Have（MVP 不做）
- 强制预算 / 超支报警
- 社交排名 / 攀比
- 投资建议 / 理财推销
- 自动扣款 / 代付

> 详细 AI vs 非 AI 对比见 §7。结论：**MVP 走"非 AI 优先"路线**，AI 作为第二层渐进叠加。

## 2. User Flow

### 核心闭环
```
[接入] → [记录] → [理解] → [连接目标] → [心安] →（回到记录，持续循环）
```

### A. 首次接入（Onboarding）
1. 欢迎语：说明"我们不打分、不批评，只帮你理解" → 建立心理安全
2. 轻量导入：引导导入一份账单（支付宝/微信），或选"稍后导入，先记一笔"
3. 建立 1 个目标：选模板（旅行/应急金/学习）或自定义，设金额 + 期限
4. 完成 → 进入心安首页

### B. 每日记录（核心，<10s）
1. 打开 App / 通知快捷入口
2. 输入金额（或导入自动生成）
3. 系统建议分类 + 可选"为什么"标签（必要/奖励自己/社交/冲动/投资）
4. 一键完成；若连目标，显示"已计入旅行基金进度"
5. 首页轻提示："记好了。这笔记完，你离 XX 目标又近了一点点。"

### C. 每周理解（轻回顾，非强制）
1. 周末温和推送（可关）："这周你为自己花了 X，为社交花了 Y，感觉平衡吗？"
2. 用户可选：给几笔打"值 / 一般 / 不值"（非评判，仅供自己看）
3. 生成一句理解："你为朋友花了不少，看来最近很重视关系。"

### D. 目标连接（持续）
1. 首页常驻目标进度条
2. 任意消费可"关联到目标"，看占比
3. 达成时庆祝（非省钱式，而是"你为想要的准备好了"）

## 3. Information Architecture

```
安记
├─ 首页（心安仪表盘）
│   ├─ 本月为未来存下 X
│   ├─ 目标进度
│   ├─ 最近记录
│   └─ 一句理解
├─ 记账
│   ├─ 记一笔（极简）
│   ├─ 导入账单
│   └─ 流水列表
├─ 洞察
│   ├─ 消费趋势（分类 / 环比）
│   ├─ 为什么（标签分布）
│   └─ 轻回顾
├─ 目标
│   ├─ 我的目标
│   ├─ 新建目标
│   └─ 目标详情（进度 / 关联消费）
└─ 我的
    ├─ 账户管理
    ├─ 导入设置
    └─ 偏好（语气 / 提醒频率）
```

**设计取舍**：把"记账"和"洞察"分开——记录时极简不打断，理解时再深入；"目标"独立成塔，强调"连接未来"。

## 4. 三个核心页面

### 页面一：心安首页（Home / Peace Dashboard）
- **目的**：用户打开 App 第一眼获得"掌控感与心安"，而非焦虑。
- **布局**：
  - 顶部：本月为未来存下 ¥X（大数字，正向）
  - 主区：2–3 个目标进度环/条（温和配色）
  - 次区：最近 3 笔 + "为什么"标签小圆点
  - 底部：一句理解文案（动态生成，非评判）
- **关键交互**：下拉刷新**不**显示"超支警告"；进度用"已准备 X%"而非"还差 Y%"。
- **文案示例**：「7月你为旅行存下了 ¥820，离海岛还差一小段，但每一步都算数。」

### 页面二：记一笔（Quick Log）
- **目的**：最低摩擦记录，10 秒内完成。
- **布局**：
  - 大数字键盘（默认弹出）
  - 金额输入区
  - 智能分类 chip（系统建议置顶，可改）
  - 可选"为什么"标签行（图标化：🍜必要 / 🎁奖励 / 👥社交 / ⚡冲动 / 🌱投资）
  - 关联到目标（可选，下拉）
  - 完成按钮「记好了」
- **关键交互**：金额输入后自动带出上一次/同类商户的分类；支持"稍后分类"暂存。

### 页面三：消费洞察 / 轻回顾（Insight & Reflection）
- **目的**：把"花了"变成"为什么花、值不值、连到哪"。
- **布局**：
  - tab1 趋势：分类环形图 + 月度环比，纯展示不评判
  - tab2 为什么：各"为什么"标签金额分布（必要 vs 奖励 vs 冲动）
  - tab3 回顾：温和问题 + 用户自评分（值/一般/不值），仅自己可见
  - 底部"连到目标"：显示某类消费对目标的贡献或占用
- **关键交互**：所有提问用第二人称但不带指责；评分不排名、不对外。

## 5. 数据模型

### 实体与关键字段

**User（用户）**
- `id`, `name`, `created_at`, `preference_tone`（gentle/strict）, `reminder_freq`

**Account（账户）**
- `id`, `user_id`, `type`（alipay/wechat/creditcard/bank/cash）, `name`, `balance`, `linked_goal_id?`

**Transaction（交易流水）**
- `id`, `user_id`, `account_id`, `amount`, `currency`, `occurred_at`, `merchant`, `raw_description`
- `category_id`, `why_tag`（necessary/reward/social/impulse/invest）
- `goal_id?`（关联目标）, `note?`, `value_rating?`（1–5 自评分）, `source`（manual/import/ocr）

**Category（分类）**
- `id`, `name`, `icon`, `is_custom`, `default_why_tag?`

**Goal（目标）**
- `id`, `user_id`, `name`, `emoji`, `target_amount`, `current_amount`（派生）, `deadline?`, `created_at`, `status`（active/done）

**WhyTag（为什么标签）**
- `id`, `code`, `label`, `icon`

**Reflection（轻回顾记录）**
- `id`, `transaction_id` / `period`, `question`, `user_answer`, `created_at`

**Insight（生成的理解）**
- `id`, `user_id`, `type`（trend/why/goal）, `content`, `period`, `generated_at`, `model?`（rule/ai）

> **关系**：User 1—N Account / Goal / Transaction；Transaction N—1 Category / Account / Goal? / WhyTag；Goal 1—N Transaction（关联）。

## 6. AI 使用场景

> **约束**：所有 AI 输出须通过"非评判式语气过滤器"，禁止指责性措辞。

| 场景 | 输入 | AI 产出 | 价值 |
|---|---|---|---|
| 智能分类 | 商户名/描述 | 分类 + 置信度 | 降记录成本 |
| 语义理解"为什么" | 商户+金额+时间 | 建议 why_tag（如星巴克→社交/自我奖励） | 自动打标签 |
| 截图 OCR 记账 | 支付截图 | 结构化交易 | 零输入 |
| 对话式查询 | 自然语言 | 数据回答 | 降低分析门槛 |
| 非评判式月度回顾 | 全月数据 | 温柔总结句 | 情感价值 |
| 目标连接建议 | 消费结构 | "你常喝奶茶，要不要设个'小确幸基金'？" | 主动连接 |
| 温和趋势提示 | 环比异常 | "这月外卖多，是不是忙？"（提问非警告） | 理解而非指责 |

## 7. 非 AI 方案对照

| 能力 | AI 方案 | 非 AI 方案（MVP 可行） | 对照结论 |
|---|---|---|---|
| 分类 | NLP 商户理解 | 关键词规则引擎 + 用户手动选 | 规则可达 ~80% 准确率，MVP 先用规则 |
| OCR 记账 | 视觉模型 | 银行/支付 CSV 导出导入 | 导入覆盖主流场景，零模型成本 |
| 为什么标签 | 模型推断 | 用户手动点标签（图标化） | 手动稍烦但零误判，且更"自知" |
| 月度回顾 | 生成式文案 | 模板化固定句 + 变量填充 | 模板生硬但安全可控 |
| 对话查询 | LLM | 筛选/搜索 UI + 图表 | UI 够用，AI 为加分项 |
| 目标建议 | 推荐模型 | 预设目标模板库 | 模板足够启动 |

**结论与建议**
- MVP 采用"**非 AI 优先**"路线：规则分类 + 账单导入 + 手动标签 + 模板文案，可独立上线，风险与成本低。
- AI 作为"**第二层**"渐进叠加：先上 OCR/智能分类（降摩擦），再上月度回顾/对话（升情感）。
- 这样既不阻塞 MVP，又给 AI 明确的价值锚点（降摩擦 + 升共情）。

## 8. 产品指标

**北极星指标（North Star）**：周均"心安度"自评分（1–5，首页轻问）+ 周活跃记录天数。
> 理由：产品成功 = 用户**持续记录且感到心安**，而非省钱额。

**采用 / 激活**
- 注册 → 完成首笔记录 转化率（目标 ≥ 60%）
- 完成 ≥1 账户/账单导入 比例
- 建立 ≥1 目标 比例（目标 ≥ 70%）

**记录成本（核心差异化）**
- 平均每笔记录耗时（目标 ≤ 10s）
- 记录完成率（开始记 → 完成，目标 ≥ 95%）
- 导入解析成功率

**留存**
- D1 / D7 / D30 留存
- 周活跃记录天数（WAR days）

**理解 & 连接**
- "为什么"标签覆盖率（有标签交易 / 总交易）
- 洞察页周访问率
- 消费关联到目标 的比例 / 人数占比

**情感（护栏指标）**
- 心安度 NPS（正向）
- "被评判/焦虑"负面反馈率（须 ≤ 阈值，红色护栏）
- 提醒关闭率（过高说明打扰）

**商业（远期，MVP 不考核）**
- 高级洞察/规划 付费转化（后续）
